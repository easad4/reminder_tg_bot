# 🤖 Task-Bot — Telegram-бот для задач и напоминаний

Telegram-бот с полностью кнопочным интерфейсом на русском языке.
Управление задачами, напоминания, повторяющиеся задачи, ежедневная сводка.
Разворачивается на чистом Ubuntu VPS одной командой.

## ✨ Возможности

- **Кнопочный интерфейс.** Никаких команд — всё через `ReplyKeyboard` и `InlineKeyboard`.
- **Пошаговый мастер создания задачи**: название → описание → дата (календарь) → время → приоритет → напоминание → подтверждение.
- **Разделы списка**: Мои задачи, Сегодня, Просроченные, Выполненные.
- **Действия над задачей**: ✅ Выполнено, 📝 Редактировать, ⏰ Отложить, 🗑 Удалить (с подтверждением).
- **Автоматические напоминания** через APScheduler: за день / час / 15 минут / точно в срок.
- **Кнопки из напоминания**: `✅ Выполнено`, `⏰ +5 минут`, `⏰ +15 минут`, `📝 Открыть задачу`.
- **Повторяющиеся задачи**: daily / weekly / monthly (следующая копия создаётся при выполнении).
- **Часовой пояс** пользователя (в БД — UTC, показывается в TZ пользователя).
- **Ежедневная сводка** в настраиваемое время.
- **Восстановление напоминаний** после перезапуска контейнера.
- **Изоляция данных**: каждый пользователь видит только свои задачи (проверка владельца во всех запросах).
- **Постоянное хранилище**: SQLite в Docker volume, данные не теряются при обновлении.
- **Полное удаление одной командой** с сохранением бэкапов (см. [Удаление](#-удаление)).

## 🚀 Быстрый старт

Кратко — для тех, кто уже знает, что делает:

```bash
# 1. Создайте бота в @BotFather и получите токен
# 2. На VPS выполните:
curl -fsSL https://raw.githubusercontent.com/easad4/reminder_tg_bot/main/install.sh -o install.sh \
  && REPO_URL=https://github.com/easad4/reminder_tg_bot.git sudo -E bash install.sh
# 3. Введите токен по запросу скрипта
# 4. Откройте бота в Telegram и отправьте /start
```

## 🤖 Создание бота в @BotFather

1. Откройте Telegram, найдите **@BotFather**.
2. Отправьте `/newbot`.
3. Укажите **имя бота** (отображается в чате), например `Мои задачи`.
4. Укажите **username**, заканчивающийся на `bot`, например `my_tasks_2025_bot`.
5. Скопируйте **токен** вида `123456789:AAE...` — это ваш `BOT_TOKEN`.
6. (Опционально) `/setdescription`, `/setuserpic`, `/setcommands` для оформления.

> ⚠️ Никогда не публикуйте токен и не коммитьте `.env` в git.

## 🖥 Подготовка VPS

Минимальные требования:

- Ubuntu **22.04** или **24.04** (x86_64 / aarch64).
- **1 vCPU, 1 GB RAM, 5 GB диска** — достаточно.
- Root-доступ или sudo-пользователь.
- Открытый **порт 22** (SSH). Дополнительные входящие порты **не нужны** — бот работает по long-polling.

Подключитесь к серверу:

```bash
ssh root@<IP-адрес-VPS>
```

Установите базовые утилиты (если их нет):

```bash
apt-get update && apt-get install -y git curl ca-certificates
```

## 📦 Установка одной командой

> **Важно.** Команда `curl | bash` может скачать скрипт только откуда-то из интернета.
> Пока вы не опубликовали репозиторий — одношаговой установки не существует.
> После публикации на GitHub (или другом публичном git) используйте одну из команд ниже.

### Вариант A. Скрипт из репозитория + явный `REPO_URL`

```bash
curl -fsSL https://raw.githubusercontent.com/easad4/reminder_tg_bot/main/install.sh -o install.sh \
  && REPO_URL=https://github.com/easad4/reminder_tg_bot.git sudo -E bash install.sh
```

### Вариант B. Скрипт лежит на вашем домене, `REPO_URL` вшит в него

Если вы правите `install.sh` и подставляете URL репозитория по умолчанию:

```bash
curl -fsSL https://ваш-домен/install.sh -o install.sh && sudo bash install.sh
```

### Что делает установщик

1. Проверяет ОС, права, архитектуру.
2. Ставит **Docker** и **docker compose plugin**, если их нет (с `systemctl enable --now docker`).
3. Создаёт каталог `/opt/task-bot`.
4. Клонирует репозиторий (`git clone`) или обновляет (`git pull`) существующий.
5. Запрашивает **токен** бота (`read -s`, не попадает в логи и `~/.bash_history`).
6. Создаёт `/opt/task-bot/.env` с правами `600`.
7. Создаёт каталог `/opt/task-bot/data` (chmod 700) — постоянный volume для SQLite.
8. Собирает образ (`docker compose build`).
9. Запускает контейнер (`docker compose up -d`) с `restart: unless-stopped`.
10. Через 5 секунд проверяет, что контейнер `running` — иначе печатает логи и падает.

### Идемпотентность

Повторный запуск `install.sh`:

- не трогает существующий `.env`;
- обновляет код (`git pull --ff-only`);
- пересобирает и перезапускает контейнер;
- **не удаляет** каталог `data/`.

```bash
cd /opt/task-bot
docker compose ps
docker compose logs --tail=80
```

Ожидаемо в логах:

```
... INFO bot: Bot started
... INFO services.reminders: Scheduler started
... INFO services.reminders: Restored N pending reminders
```

1. Откройте своего бота, отправьте `/start`.
2. Появится клавиатура с кнопками: `📋 Мои задачи`, `➕ Создать задачу`, …
3. Нажмите **➕ Создать задачу** → пройдите мастер.
4. Дождитесь напоминания (можно выбрать «Точно в срок» и время через 2 минуты).

## 🎛 Управление

Интерактивное меню:

```bash
cd /opt/task-bot
bash manage.sh
```

Прямые команды:

```bash
bash manage.sh logs       # docker compose logs -f --tail=200
bash manage.sh restart    # перезапуск
bash manage.sh stop       # остановить
bash manage.sh start      # запустить
bash manage.sh status     # docker compose ps
bash manage.sh update     # git pull + rebuild + up -d
bash manage.sh backup     # создать бэкап
bash manage.sh restore backups/tasks-YYYYMMDD-HHMMSS.db
```

Обычные `docker compose` команды тоже работают — `manage.sh` лишь обёртка.

## 🔄 Обновление

```bash
cd /opt/task-bot
bash manage.sh update
```

Что происходит:

1. `git pull --ff-only` — подтягивает новый код.
2. `docker compose build` — собирает новый образ.
3. `docker compose up -d` — пересоздаёт контейнер.

**Данные не теряются**: SQLite лежит в `./data/tasks.db` на хосте, `.env` не изменяется.
После старта бот восстанавливает все несданные напоминания из таблицы `reminders`.

## 💾 Резервное копирование

Создать бэкап:

```bash
cd /opt/task-bot
bash backup.sh
# → backups/tasks-20260101-120000.db
```

Скрипт использует `sqlite3.Connection.backup()` внутри контейнера — дамп согласованный, даже если бот пишет прямо сейчас.
Автоматически хранит последние **10** бэкапов, старые удаляет.

Восстановить:

```bash
bash restore.sh backups/tasks-20260101-120000.db
```

Текущая база сохраняется как `data/tasks.db.bak-<timestamp>` перед перезаписью.

### Автоматический бэкап по расписанию (опционально)

Добавьте в crontab root:

```cron
0 3 * * * cd /opt/task-bot && bash backup.sh >> /var/log/task-bot-backup.log 2>&1
```

> Если позже будете удалять бота, не забудьте убрать эту строку (`crontab -e`).

## 🗑 Удаление

Полное удаление бота с VPS одной командой. Скрипт **не трогает** Docker, системные пакеты, SSH и firewall — удаляет только сам бот.

### Интерактивный режим (рекомендуется)

```bash
cd /opt/task-bot
sudo bash uninstall.sh
```

Показывает, что будет удалено, спрашивает подтверждение на каждом шаге. Бэкапы БД по умолчанию **сохраняются** в `/root/task-bot-backups-<timestamp>/`.

### Быстрое удаление (без вопросов, бэкапы оставить)

```bash
sudo bash uninstall.sh --yes
```

### Полное удаление, включая бэкапы и `.env`

```bash
sudo bash uninstall.sh --purge-all
```

### Флаги

| Флаг | Действие |
|------|----------|
| *(без флагов)* | интерактивно; бэкапы сохраняются в `/root/task-bot-backups-<ts>/` |
| `--yes` / `-y` | без подтверждений; бэкапы всё равно сохраняются |
| `--keep-backups` | явно оставить бэкапы (это и так поведение по умолчанию) |
| `--purge-all` | удалить всё, включая бэкапы и `.env`; подразумевает `--yes` |
| `--help` / `-h` | показать справку |

### Что удаляется

- Docker-контейнер `task-bot`
- Docker-образ `task-bot:latest` (с подтверждением)
- Каталог `/opt/task-bot` (с подтверждением)
- `.env`, `data/`, `backups/` — если не передан `--keep-backups` и не выбран `--purge-all`

### Что НЕ удаляется (сознательно)

- Docker и его образы для других приложений
- Системные пакеты (`git`, `curl`, `docker-ce`)
- SSH-конфиг, firewall, cron
- Пользовательские данные вне `/opt/task-bot`

### После удаления — обязательно

1. **Отзовите токен бота** в Telegram: @BotFather → `/mybots` → выбрать бота → **API Token** → **Revoke current token**. Иначе старый токен останется валидным.
2. **Удалите cron-задачу**, если настраивали автобэкап:
   ```bash
   crontab -e
   ```
3. **Проверьте, что ничего не осталось**:
   ```bash
   docker ps                 # нет контейнера task-bot
   docker images | grep task-bot
   ls /opt/task-bot 2>/dev/null || echo "каталог удалён"
   ```

### Идемпотентность

Повторный запуск `uninstall.sh` после успешного удаления:

- видит, что `/opt/task-bot` отсутствует;
- печатает «каталог не найден, возможно бот уже удалён»;
- завершается с кодом `0`.

Никаких ошибок при отсутствии Docker тоже не будет — проверки обёрнуты в `if command -v docker`.

## 🐞 Частые проблемы

**Контейнер падает сразу после старта**

```bash
docker compose logs --tail=100
```

Частые причины:

- неверный `BOT_TOKEN` → `Unauthorized`;
- `BOT_TOKEN` начинается с пробела/кавычек в `.env`;
- нет прав на `/data` (исправляется `chmod 700 /opt/task-bot/data`).

**Бот не отвечает на `/start`**

- Убедитесь, что контейнер `running`: `docker compose ps`.
- Проверьте логи: `docker compose logs -f`.
- Проверьте, что не запущен второй экземпляр бота с тем же токеном (Telegram вернёт `Conflict`).

**Напоминания не приходят**

- Смотрите логи: `docker compose logs -f | grep -i remind`.
- Проверьте, что время задачи в будущем относительно **UTC** в БД (`due_utc`).
- Проверьте часовой пояс в настройках бота — напоминания планируются в UTC, но показываются в TZ пользователя.

**Ошибка `docker compose version not found`**

Обновите Docker или установите плагин:

```bash
apt-get install -y docker-compose-plugin
```

**`ModuleNotFoundError: No module named 'handlers'` при локальном запуске**

Проверьте, что во всех подпапках (`handlers/`, `services/`, `keyboards/`, `states/`) есть пустые файлы `__init__.py`.

## 🔒 Безопасность

- **Токен** хранится только в `.env` (chmod 600) и в переменных окружения контейнера.
- **Параметризованные SQL** — все запросы в `services/*.py` идут через `?`-плейсхолдеры.
- **Проверка владельца** во всех операциях: `WHERE id=? AND user_id=?`.
- **Изоляция данных**: каждый пользователь видит только свои задачи.
- **Firewall не отключается**, входящие порты не открываются.
- **Логи** — без токена (`aiogram` не печатает токен при стандартном логгировании; не выводите `config.BOT_TOKEN` вручную).
- **Docker volume** для БД вынесен на хост: `./data → /data`.
- **`.gitignore`** исключает `.env`, `data/`, `backups/` — секреты не попадут в репозиторий.

Если что-то пошло не так и вы подозреваете утечку токена — отзовите его в @BotFather (`/mybots` → бот → **Revoke token**) и обновите `.env`, затем `docker compose up -d`.
